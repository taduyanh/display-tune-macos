# DisplayTune

Menu-bar app (Apple Silicon, macOS 14+) for external monitors:
- **Hardware brightness** over DDC/CI (works when macOS has no brightness slider for the monitor)
- **Software dim** (gamma) as an extra / fallback
- **Resolution, HiDPI and refresh rate** switching, plus a "High Resolution (HiDPI)" toggle (same size, 2x <-> 1:1, like BetterDisplay's)
- **Brightness keys (F1/F2)** drive the external display under the mouse pointer (1/16 steps, ⇧⌥ = fine steps) with an on-screen indicator. Needs *Accessibility* permission. Keys on the built-in display are untouched.
- **Extra HiDPI sizes** for panels macOS gives no HiDPI for (e.g. QHD monitor at "looks like 1920x1080") — experimental

## Build / install
```
./build.sh            # builds build/DisplayTune.app
./build.sh install    # also copies it to ~/Applications
```
Source: `Sources/*.swift`, private-API declarations: `Bridge.h`. No Xcode project needed (swiftc only).

## CLI (same binary)
```
DisplayTune.app/Contents/MacOS/DisplayTune --cli list
DisplayTune.app/Contents/MacOS/DisplayTune --cli brightness 0 70
DisplayTune.app/Contents/MacOS/DisplayTune --cli mode 0 1920x1080 hidpi 120
DisplayTune.app/Contents/MacOS/DisplayTune --cli keystep 0 up   # simulate one brightness-key press
DisplayTune.app/Contents/MacOS/DisplayTune --cli menu      # prints the menu structure
DisplayTune.app/Contents/MacOS/DisplayTune --cli bench 1000 # rebuilds the menu 1000x, reports time + memory (leak check)
```
Exit status: 0 ok, 1 operation failed, 2 bad usage.

## How it works (same building blocks BetterDisplay links against)
| Feature | API |
|---|---|
| Hardware brightness | `IOAVServiceCreateWithService` / `IOAVServiceWriteI2C` / `ReadI2C` (private, resolved with `dlsym`). DDC/CI VCP code `0x10`, I2C address `0x37`. The `DCPAVServiceProxy` (Location=External) that follows each `AppleCLCD2` node in the IORegistry is the channel for that display. |
| Software dim | `CGSetDisplayTransferByFormula` (only lasts while the app runs) |
| Resolution / HiDPI / Hz | public `CGDisplayCopyAllDisplayModes` + `CGConfigureDisplayWithDisplayMode` |
| Extra HiDPI (non-Retina panels) | private `CGVirtualDisplay` (hiDPI=1, e.g. 1920x1080 → 3840x2160 backing store) + `CGConfigureDisplayMirrorOfDisplay` so the physical panel mirrors it and the GPU downsamples. Asks "Keep / Revert" and auto-reverts after 15 s. |

## Building on another Mac
Needs macOS 14+ and the Xcode Command Line Tools (`xcode-select --install`). No certificate or Apple Developer account.
```
./build.sh install              # builds, ad-hoc signs and copies to ~/Applications
open ~/Applications/DisplayTune.app
```
- A locally built app is not quarantined, so Gatekeeper does not block it (a *downloaded* pre-built copy would be).
- Brightness over DDC needs an Apple Silicon Mac; on an Intel Mac the brightness slider shows "DDC not available" and the keys use software dimming (resolution/HiDPI features still work).
- Grant *Accessibility* once for the brightness keys. An ad-hoc signature changes on **every rebuild** and invalidates that permission. Run `./tools/make_signing_cert.sh` once: it creates a self-signed identity in its own keychain (`~/Library/Keychains/displaytune-signing.keychain-db`, nothing in your login keychain, no trust changes, no password prompts) and `build.sh` then signs with it automatically, so the permission survives rebuilds. After switching from ad-hoc to this identity (or the other way round) reset once: `tccutil reset Accessibility dev.taduyanh.DisplayTune`.
- The identity is local to each Mac and is not needed to *run* the app — only to sign builds.
- To publish the source, change `CFBundleIdentifier` in `Info.plist` (and the `dev.taduyanh` prefix) to your own.

## Notes / limits
- The app is ad-hoc signed, so macOS ties the Accessibility permission to the exact build: after rebuilding, remove and re-add DisplayTune in *System Settings → Privacy & Security → Accessibility* if the brightness keys stop responding.
- Every external display exposes a DDC endpoint, but only a monitor that actually answers is treated as DDC-capable; otherwise the slider says "DDC not available" and the brightness keys fall back to software dimming.
- A monitor connected through some docks/HDMI adapters may not pass DDC; enable "DDC/CI" in the monitor's OSD if brightness shows "not available".
- Software dim resets when the app quits.
- Extra HiDPI is session-only (not restored at login) and has not been tested on a QHD panel yet.
- Not notarized (signed with a local identity or ad-hoc); it is built locally, so Gatekeeper does not block it.
